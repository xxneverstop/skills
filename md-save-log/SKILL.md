执行 `$task` 描述的功能优化、改进或新功能操作，完成后将变更记录保存为 markdown 文件。

## 适用范围

本技能面向以下类型的操作：
- 功能优化或改进（性能、体验、逻辑修正）
- 新功能开发
- 项目重构（结构调整、代码整理）
- 工具/库/依赖的引入或替换
- 部署配置变更（CI/CD、环境变量、构建脚本）
- 配置文件、文档、脚本等任何会改动项目的操作

## 执行流程

### 第一步：理解需求

分析 `$task`，明确：
- 要改什么？为什么改？
- 涉及哪些文件、模块？
- 改动的影响范围有多大？

### 第二步：执行操作

直接动手做。读源码、改代码、跑命令——该做什么做什么，把需求落地。遵循项目现有代码风格和惯例。

### 第三步：记录变更

操作完成后，将本次变更保存为 markdown 文件。记录内容包括：

1. **变更概述** — 一两句话说清楚做了什么、为什么做
2. **变更前后对比** — 关键改动的前后行为/代码对比（不是逐行 diff，是让人看懂的对比）
3. **涉及文件** — 列出改动的文件路径及改动性质（新增/修改/删除）
4. **注意事项** — 如果有的话：依赖更新、配置变更、后续需要关注的点、可能的副作用
5. **验证方式** — 如何确认改动生效（如果有测试或验证步骤）

## 写作风格

- 用中文写，代码/命令/文件名保持原文
- 面向未来的自己和其他开发者——几个月后回来看这份记录，要能快速理解当时做了什么、为什么那么做
- 简洁但不遗漏关键信息
- 自然段落为主，不堆砌 bullet

## 输出

1. **确定文件路径**：默认保存到当前工作目录，文件名根据变更主题推导 kebab-case（40 字符以内），如 `add-retry-mechanism.md`、`migrate-to-vite.md`
2. **写文件**：文件开头添加 `> 记录于 YYYY-MM-DD HH:MM`，然后是正文
3. **报告**：一行——文件路径 + 字数
